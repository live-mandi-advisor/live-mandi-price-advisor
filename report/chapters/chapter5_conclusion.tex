\chapter{Conclusion, Future Scope, Limitations}

\section{Conclusion}
This project has implemented a complete agricultural price forecasting
system demonstrating the full ML pipeline -- from raw data ingestion
through model training and evaluation to a working web application.
Starting from 11.3 million raw Agmarknet records, the system ingested
1{,}185{,}657 cleaned price records across 3 states, 18 commodity
combinations, and 1{,}372 markets. It trained 2{,}347 Prophet models,
evaluated them against a naive baseline, generated 17{,}451 precomputed
7-day forecasts, and served them through a FastAPI backend and React
frontend.

The system is presented as a \textbf{historical-data demonstration},
using data as of 29 December 2025. Live data ingestion is designed but
not operationally deployed; this is explicitly disclosed in the
application interface. The core contribution is a reproducible,
end-to-end pipeline that could be extended to live operation once a
reliable data source is confirmed.

\section{Limitations}
\begin{itemize}
    \item \textbf{Historical-only data.} The demonstration uses data
    ending 29 December 2025. Forecast dates are therefore in late 2025
    to early 2026, not the current date. The application discloses this
    explicitly. Live ingestion is designed (Section~3.2.3) but was not
    operationally deployed due to Agmarknet API reliability issues from
    cloud runners.
    \item \textbf{Variety averaging.} Modal prices are averaged across
    all reported varieties per (commodity, market, date). For commodities
    with real grade splits (Onion 1st/2nd sort, Coconut Big/Medium/Small),
    this blends different price tiers if the grade mix shifts over time.
    \item \textbf{Naive baseline dominance.} The naive trailing-average
    baseline outperformed Prophet on 80\% of evaluated pairs by normalized
    MAE. This is a documented finding (Chapter~4), not a system failure --
    it reflects the noisy, mean-reverting nature of short-horizon mandi
    price series. Prophet remains the deployment model, with the baseline
    comparison reported as an experimental result.
    \item \textbf{Sparse markets excluded.} Markets with fewer than 180
    distinct reporting days were not eligible for Prophet training, excluding
    approximately 65\% of all (commodity, market) combinations in the
    database. These are predominantly thin or sporadically reporting markets.
    \item \textbf{No deployment.} The working system runs locally; cloud
    deployment was not completed within the project timeline.
\end{itemize}

\section{Future Scope}
The architecture supports several natural extensions without structural
redesign:
\begin{itemize}
    \item \textbf{Live data ingestion:} connecting the existing pipeline
    design to a reliable Agmarknet data feed would make forecasts current.
    \item \textbf{Per-commodity model selection:} applying the naive
    baseline for commodities where it consistently wins (e.g.\ Tomato)
    and Prophet only where it adds value (e.g.\ Snakeguard) would improve
    forecast accuracy.
    \item \textbf{Additional states and commodities:} the schema and
    pipeline are not state-specific; wider coverage requires only
    additional backfill and retraining.
    \item \textbf{Explainability:} SHAP or LIME layers on the forecast
    output to build farmer trust and support academic evaluation.
    \item \textbf{Regional language and SMS delivery:} Sell/Hold alerts
    delivered via SMS in regional languages for farmers without reliable
    internet access.
    \item \textbf{Weather feature integration:} incorporating rainfall
    or temperature data as additional Prophet regressors for
    weather-sensitive crops.
\end{itemize}
